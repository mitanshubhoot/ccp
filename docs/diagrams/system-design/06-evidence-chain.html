06 · ER / data model · CCP target architecture

The evidence chain behind every verdict

One chain from a raw provider page to the read that confirmed a fix: evidence, FAIL, lookups, investigation, suggestion, confirming verdict. Rows are appended and superseded, never edited.

APPEND ONLY

History is kept

  • Verdicts and state rows are insert-only; a correction supersedes with a reason and never rewrites.
  • As-of queries show what was true, and what CCP believed, at any time.

REBUILDABLE

Verdicts carry their inputs

  • rule_version and the manifest of pinned inputs identify each verdict.
  • Model requests and responses are stored, so an AI-derived verdict is rebuilt from stored outputs, never re-sampled.

VERIFIABLE

Without trusting the database

  • A per-tenant hash chain covers raw objects and every row above.
  • Hourly signed checkpoints sit in a compliance-mode bucket in a separate account; ccp audit verify checks them.
  • As-of audit packages carry raw pointers and chain proofs and verify offline with a public key.
