05 · State machine · CCP target architecture

The life of a fix suggestion

CCP suggests fixes and applies none. Code renders and checks each one; a person may accept or dismiss it, but only a later read of the customer's systems confirms it, and a FAIL within 30 days reopens it.

RENDERED

Code writes what is shown

  • The model, or code when the rule explains the failure, picks a fix by id and its parameters. It never writes a command or a diff.
  • Code fills the versioned template and checks params, commands, syntax, scope and placeholders. A failure is recorded, never offered.

NO EXECUTION

The customer applies it

  • No pull request, write credential or executor. The suggestion is a Terraform change, commands and console steps to copy.
  • Accept and dismiss are records; a dismissal says why.

DONE MEANS READ

Confirmed by evidence

  • A verdict on evidence observed after the suggestion that no longer names the resource confirms it.
  • ccp fixes metrics reports time to confirm and the 30-day reopen rate.
