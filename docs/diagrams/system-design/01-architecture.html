01 · Architecture · CCP target architecture

Code decides, models propose, people approve

Evidence flows left to right through code that sets every status. Agents read through one gateway and can only propose; code renders each fix, the customer applies it, and only the next sync confirms it.

CODE DECIDES

Every status comes from a rule

  • A versioned rule over pinned facts sets PASS, FAIL or PARTIAL. Tier-2 models only extract typed fields, with pointer citations that code checks.
  • Absence counts only from a complete sync; a partial or denied read gives needs_review.
  • Verdict, state row and announcement commit in one transaction.

MODELS PROPOSE

Agents read, then propose

  • Agents run as bounded queue jobs (turns, tokens, cost, time), at most one run per evidence state.
  • Every tool is typed, bound to the tenant in code and checked by a fail-closed policy.check. Code, not the model, chooses every live read.
  • A run ends with a draft or a fix chosen by id from the catalogue, never a write.

PEOPLE DECIDE

Suggest, never apply

  • Code renders the Terraform change, commands and console steps from a versioned template and checks them offline before anyone sees them.
  • A signed-in member approves drafts by payload hash, never the requester; accepting a fix is a record only.
  • No pull request, executor or write credential: a fix is confirmed only when a later read sees it.
