03 · Sequence · CCP target architecture

A public S3 bucket, from first read to a confirmed fix

The AWS worked example, suggest-only: a rule finds the bucket open, code looks up who changed it and where it lives in Terraform, renders a checked fix, the customer applies it, and the next read confirms it.

DETECT

Code finds the FAIL

  • Every page lands write-once with a hash and a completeness record before it is mapped.
  • The failing rule names the bucket, so the rule itself explains the failure: no model is needed and nothing parks.

LOOK UP

Code picks every read

  • Config history in 7-day windows, the CloudTrail events that can change the setting, and a search of the organization's Terraform; 10 resources and 30 days at most.
  • Each response lands raw before its typed row. A model never chooses a live read or its parameters.

SUGGEST AND CONFIRM

Applied by the customer

  • Code fills the fix's template and checks parameters, commands, syntax and scope; a fix that fails a check is never offered.
  • Accepting is a record. Only a verdict on evidence observed after the suggestion confirms it; a FAIL within 30 days reopens it.
